这一阶段把真实田间小区记录整理成“环境 × 材料”样本，并准备好产量目标、基因型、播种日期和逐日天气之间的连接。它不是预测结果，也不代表模型已经有效。

## 2. 已执行的整理规则

1. **目标粒度统一。** 同一环境、同一材料的有效小区产量取算术平均；缺失、非有限或非正产量不用于均值，也不填零。重复小区数和产量离散程度只留作审计，不能作为预测特征。
2. **播种日期补齐。** 优先原记录；缺失时仅使用同一环境 × 材料的唯一已知日期，再尝试同一环境的唯一日期。日期的选择不依据产量大小或是否有产量。
3. **多播种日期不强行合成一个真实日期。** 保留各个日期及其小区数权重；后续按日期分别提取天气再加权。一个组合的整个窗口信息要到最晚子窗口截止时才完整可用。
4. **处理天气暴露与标签不对齐。** 全部候选中有 173 个训练/验证组合，其有标签小区的日期分布与全部小区不同。主分析排除这类组合，在此前筛选之后额外减少 169 条；明细保留，未来可做敏感性分析。此规则未用于按 2024 标签筛选测试输入。
5. **固定共同样本。** W0、W30、W60、W90、W120 使用相同的各期样本集合。所需日历日期不全的组合排除；有日期但某天气数值缺失的情况保留并记录，留待下一阶段处理。该完整日历筛选也限定了研究适用范围，不能代表所有原始田间试验。
6. **明确天气边界。** W30 表示 `[播种日, 播种日 + 30 天)`，其他窗口同理。下一步必须先截断窗口，再补值/汇总，不能利用窗口之后的天气。
7. **按年份隔离。** 2014–2022 训练，2023 选模型，2024 最终评估，不做随机混合拆分。相同材料跨年出现允许，环境—年份不会跨集合重复。
8. **Stage 1 保留缺失而非提前拟合。** 本阶段导出中的基因型缺失、坐标缺失与天气数值缺失不做填补；不执行 PCA、标准化或模型训练，相关拟合属于后续建模阶段。保留的基因型维表含 5,893 个材料、2,425 个原始标记。

完整机器可读规则：[data_contract.json](outputs/data_contract.json)。

## 3. 交付文件怎么用

| 文件/目录 | 用途 | 是否可直接作为预测输入 |
|---|---|---|
| `outputs/samples/train.csv`、`validation.csv`、`test.csv` | 样本主键、年份、地点与播种日期 | 只能按特征白名单使用 |
| `outputs/targets/train.csv`、`validation.csv` | 开发期产量目标 | 仅作为目标 `y` |
| `outputs/holdout/test_targets.csv` | 2024 官方观测值 | 仅在方案冻结后最终评分 |
| `outputs/dimensions/genotypes.csv.gz` | 原始数值基因型 | 下一步做训练期拟合的预处理 |
| `outputs/dimensions/weather_daily.csv.gz` | 逐日天气，包含完整原始日期 | 必须先按窗口过滤 |
| `outputs/dimensions/environments.csv` | 环境维表 | 按白名单选静态字段 |
| `outputs/links/sample_plantings.csv.gz` | 样本与播种日期的连接、权重 | 连接与天气聚合使用 |
| `outputs/links/weather_windows.csv` | 每个播种日期的 4 个窗口边界 | 控制时间可用性 |
| `outputs/audit/` | 排除原因、产量诊断、缺失和对账 | **不可合并进预测特征** |
| `outputs/manifest.json` | 输入/输出哈希、版本、规模与检查记录 | 可复现性与追踪 |

当前静态预测字段白名单为 `Experiment_Code`、`Latitude`、`Longitude`、`Planting_DOY`。`sample_id`、`Env`、`Hybrid`、`Year` 及日期最小/最大值是标识或路由字段，不因出现在样本表中就自动进入模型。

测试标签的单独存放是一项流程约定，不是操作系统权限锁；后续训练代码仍须明确禁止读取它。审计文件含结果相关信息，同样必须隔离。

## 4. 来源核验结果与边界

当前数据来自 G2F 官方发布和公开镜像，不能将全部镜像文件称为“与官方完全一致”。

- 训练元数据、2024 提交模板：已取得完整官方文件，SHA-256 与镜像完全一致。
- 2024 元数据：发现 8 个单元格差异；建模流程已切换到单独保存的官方副本，原镜像未修改。官方缺失的 3 个环境坐标在 Stage 1 导出中继续保留缺失，没有采用镜像补充值；影响 1,025 条测试输入，坐标填补属于后续训练期预处理。
- 2024 产量观测：直接取自官方，已记录哈希和结构核验。
- **训练天气、2024 天气：** 2026-10-18 已取得完整官方文件，SHA-256 与镜像完全一致。
- **训练性状：** 全部 173,960 行、26 列的值和顺序键一致；官方 CRLF 换行改为 LF 后，完整字节与镜像一致。
- **基因型：** 官方 TXT 的全部 5,899 个材料、2,425 个 SNP 值和顺序一致。去掉 `<Numeric>` 声明、将 `<Marker>` 改名为 `Geno`、将制表分隔改为逗号后，完整字节与镜像 CSV 一致。这是格式转换，不是数据值修正；5,899 是原始文件规模，不等于筛选后维表的 5,893。

四份补核验均未发现数据值差异，原镜像哈希仍与 Stage 1 冻结记录一致，因此无需重新整理或重跑 Stage 1。来源等价不保证所有农业观测都准确，也不能替代缺失、泄漏和实验评估检查。历史来源记录保留当时的待核验状态，当前结论以最新补核验报告为准。

证据：[历史来源比对记录](source_verification.json)、[最新补核验说明](provenance_followup/README.md)、[完整补核验报告](provenance_followup/verification_report.json)、[实际选用输入与哈希](outputs/manifest.json)。

## 5. 验证与复现

真实全量导出已通过独立核验脚本的 **65 项检查**，覆盖输出哈希、原始数据未改动、主键唯一性、时间拆分、独立重算产量均值、连接覆盖、窗口日历、特征白名单和官方坐标等。通过这些检查不等于证明预测有效；四份来源的完整一致性是由上述独立补核验另行确认的，不属于这 65 项检查。

仅查看已有产物时无需重新整理。核验已有输出可从项目根目录运行（Python 3.12；依赖版本见 `requirements.txt`）：

```sh
python preparation/validate_prepared_data.py
python -m unittest discover -s preparation -p 'test_prepare_data.py' -v
```

只有首次复现或处理规则确实变化时，才运行 `python preparation/prepare_data.py`。新环境依赖安装使用 `python -m pip install -r preparation/requirements.txt`；不要因此覆盖正在运行的建模环境。

`prepare_data.py` 默认读取 `audit/data/raw/`，若 `preparation/official_inputs/` 有同名官方文件则优先使用，导出至 `preparation/outputs/`。重新运行会更新这些派生输出；原始数据保持只读。实际运行环境为 Python 3.12.14、pandas 2.2.3、numpy 2.3.5。

独立对账结果：[validation_report.json](validation_report.json)。另有 [8 项边界测试](test_prepare_data.py) 已全部通过，覆盖产量均值、日期补齐、日期权重、错配排除、天气窗口右开边界、无标签测试输入、年份拆分及重复/缺失键拒绝。边界测试为小型合成输入，不替代真实数据对账。
